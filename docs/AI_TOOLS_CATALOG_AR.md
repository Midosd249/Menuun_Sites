# دليل أدوات الذكاء الاصطناعي وسير العمل لمشروع Menuun

**الإصدار:** 1.0  
**تاريخ الإعداد:** 2026-10-18  
**المستودع:** Midosd249/Menuun_Sites  
**الغرض:** مرجع تراكمي يشرح الأدوات المذكورة، ومتى نستخدم كل أداة، والناتج المتوقع منها، ومثالًا مرتبطًا بموقع Menuun. أضف الأدوات الجديدة إلى هذا الملف بدل إنشاء قوائم متفرقة.

> **قاعدة الدقة:** الأسماء الواردة ليست كلها من النوع نفسه. بعضها تكامل يمكن استدعاؤه، وبعضها مهارة أو مسار عمل، وبعضها اسم عام أو اختصار قد تختلف وظيفته حسب التطبيق. يميز هذا الدليل بين وظيفة معروفة واسم يحتاج تحققًا. ذكر أداة لا يعني أنها متصلة أو أنها نُفذت في هذه الجلسة.

## 1. ملخص تنفيذي

أفضل طريقة للاستفادة من المجموعة ليست تشغيل كل شيء في كل مهمة، بل اختيار أقل مجموعة تحقق النتيجة بأمان:

1. **فهم المطلوب:** Idea Generator، Product Design، MECE، GrillMe.
2. **بحث موثوق:** Exa، GitHub، وRAGOps عند توفر مخزن معرفة فعلي.
3. **تصميم وتجربة مستخدم:** Designly، UI UX Designer، Product Design، Awesome DESIGN.md، DesignSystem، UXCritique، UIAudit، Taste.
4. **تنفيذ:** Build، OpenCode عند توفر بيئة تنفيذ مناسبة، وBuilding React Native Apps لتطبيقات React Native.
5. **التحقق والإصلاح:** Debug، Review، HardenUI، Polish، JSON Change Lens، Cache Stats عند الحاجة.
6. **التسليم:** ToTickets، Handoff، Ship، GitHub.
7. **الأتمتة:** Zapier MCP بعد تحديد محفّز وإجراء وصلاحيات وسجل أخطاء واضح.

### مبادئ خاصة بمشروع Menuun

Menuun منصة عربية أولًا وثنائية اللغة لخدمات الصالونات والحلاقين والحجوزات. يجب أن تحافظ أي أداة على:
- العربية واتجاه RTL كمسار أساسي، والإنجليزية واتجاه LTR كمسار مدعوم.
- عدم اختلاق ميزات أو نجاحات حجز/دخول غير موجودة فعليًا.
- عدم نقل منطق الطلبات أو السلة أو الدفع من مشروع مطاعم إلى منطق مواعيد الصالونات بلا مراجعة.
- عدم كشف مفاتيح Supabase السرية أو تجاوز التحقق من العضوية والصلاحيات وعزل المستأجرين.
- عدم النشر الإنتاجي أو تغيير DNS أو إعدادات Vercel أو تنفيذ ترحيلات قاعدة البيانات من دون تفويض صريح.
- اعتبار نتيجة البناء أو الاختبار أو النشر «متحققة» فقط عند وجود دليل مباشر.

## 3. سير عمل مقترح لمهمة نموذجية

**المهمة:** تحسين رحلة إنشاء صفحة صالون ومشاركة رابط الحجز.

1. **Product Design + MECE:** تحديد مراحل الرحلة وحالات النجاح والفشل وتغطية النطاق دون تكرار.
2. **Exa + GitHub:** جمع مراجع موثوقة، ثم فحص الكود الحالي وملفات التوجيه وحالة المشروع والمعمارية والاختبارات.
3. **UXCritique + UIAudit + Designly:** كشف نقاط الاحتكاك ووضع اقتراح بصري يراعي العربية RTL والإنجليزية LTR.
4. **Awesome DESIGN.md + DesignSystem:** توثيق الرموز والمكونات والحالات قبل توسيع الواجهة.
5. **Prototype / WebMockup / MobileMockup:** اختبار الفكرة على الهاتف وسطح المكتب قبل التنفيذ الكامل.
6. **ToTickets:** تحويل الحل إلى تذاكر صغيرة ومعايير قبول.
7. **Build أو OpenCode:** تنفيذ التغيير في فرع مناسب، إذا كانت بيئة التنفيذ متاحة ومصرحًا بها.
8. **Debug + Review + HardenUI:** اختبار الحالات الحدية والصلاحيات والأمان وعدم كسر الوظائف الموجودة.
9. **Ship:** فحص CI والبناء والمعاينة، ثم طلب التفويض اللازم لأي إجراء إنتاجي.
10. **Handoff + GitHub:** توثيق ما تغير وأدلة التحقق والمجهولات والخطوة التالية.

### معايير قبول مقترحة
- لا يتغير رابط الصالون العام أو القالب المحفوظ دون قصد.
- يعمل التخطيط في RTL وLTR وعلى عروض الهاتف واللوحي والحاسوب.
- كل زر يؤدي وظيفة حقيقية، ولا توجد رسالة نجاح زائفة.
- تُفحص حالات التحميل والفراغ والخطأ وعدم الصلاحية.
- لا يمكن للعميل تغيير هوية الصالون أو صلاحياته عبر تعديل طلب المتصفح.
- تنجح الاختبارات والبناء المتاحة، وتُذكر أي اختبارات لم تُنفذ صراحةً.

## 4. كيف نجعل هذا الدليل مرجعًا دائمًا؟

1. عند ذكر أداة جديدة، أضف سجلًا لهذا الملف يشمل: **الاسم، النوع، حالة الاتصال، الوظيفة المثبتة، مثال Menuun، المدخلات/المخرجات، القيود، وآخر تحقق**.
2. لا تسجل الأداة على أنها «متصلة» لمجرد ظهور @اسم في الرسالة. تحقق من قائمة الأدوات المتاحة أو وثائقها.
3. احتفظ بالاسم الأصلي بالإنجليزية كي يسهل البحث عنه، مع شرح عربي.
4. سجّل الروابط الرسمية فقط عندما يتم التحقق منها، ولا تخمّن روابط أو أسماء وظائف.
5. قبل استعمال أداة خارجية، راجع الأذونات والتكلفة والخصوصية والترخيص وإمكانية إعادة الإنتاج.
6. اربط نتائج الأدوات بأدلة داخل المستودع: ملفات توثيق أو تذاكر أو اختبارات أو لقطات مرئية أو معرفات commits/PRs.
7. عند تحديث المستودع، افحص حالة الفرع وملفات التوجيه الحالية أولًا؛ لا تفترض أن هذا التقرير يثبت حالة الكود أو النشر.
