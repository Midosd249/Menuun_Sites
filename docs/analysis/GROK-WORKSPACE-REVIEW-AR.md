# تحليل أرشيف Grok — مرجع لموقع حلاق رجالي

تاريخ الفحص: 2026-10-12. الأرشيف الأصلي محفوظ في `public/assets/grok-workspace.zip` على الفرع `feature/salon-vertical-slice` (13,153,153 bytes). فُتح الأرشيف وفُحصت قائمة ملفاته ومجموعة من ملفات المصدر. هذا التقرير يوثق التحليل؛ لا يعني أن نسخة الحلاق الرجالي قد نُفذت بعد.

## الخلاصة

الأرشيف **ليس تصميم حلاق رجالي**؛ بل تطبيق ويب لصالون تجميل نسائي باسم «أتيليه ليان / Layan Atelier» في الرياض. محتواه يتضمن تصفيف وتلوين الشعر، الأظافر، العناية بالبشرة، وإطلالة العروس. الصور والنصوص والهوية الحالية أنثوية، لذا ينبغي عدم نسخها مباشرة إلى موقع SIMT الرجالي. استخدمه كمرجع لأفكار ترتيب الصفحة والتفاعل فقط، ثم أعد بناء المظهر والمحتوى بما يناسب الحلاقة الرجالية.

## الجرد والبنية

- يحتوي ZIP على 375 عنصرًا بما فيها المجلدات.
- مجلد `.grok/` يضم 124 عنصرًا من إعدادات ومرجعيات ومهارات بيئة Grok.
- المصدر في `src/`، والأصول في `public/images/`.
- `.vercel/output/` يحتوي نواتج بناء مجمعة، وليس مصدرًا مناسبًا للتعديل المباشر.
- توجد ملفات إعداد وسكربتات واختبارات مثل `package.json`, `vite.config.ts`, `scripts/`, `server/`.
- تتضمن الحزمة ملفات Grok/PWA وVercel لا ينبغي نسخها إلى المشروع الحالي دون مبرر ومراجعة توافق.

## التقنية

الأرشيف ليس Next.js؛ إنه تطبيق React وTypeScript يستخدم Vite وTanStack Router/Start وTailwind CSS 4. يجب نقل الأفكار الملائمة يدويًا إلى بنية المشروع الحالي بدل استبدال إعداداته أو اعتمادياته.

ملفات المصدر التي فُحصت:
- `src/routes/index.tsx`: صفحة رئيسية تجمع Hero وServices وStory وGallery وExperience وVisit، وmetadata تشير صراحة إلى صالون نسائي.
- `src/routes/book.tsx`: مسار الحجز.
- `src/lib/salon.ts`: اسم العلامة والمدينة والخدمات والأسعار والمدد والنصوص.
- `src/components/salon/hero.tsx`: الصورة الرئيسية والعنوان وأزرار الإجراء.
- `src/components/salon/services.tsx`: مقاطع خدمات بصور ونصوص متناوبة.
- `src/components/salon/booking-form.tsx`: نموذج طلب موعد تجريبي.
- `src/styles.css`: ألوان عاجية وكريمية وبنية، وخط Amiri للعناوين وIBM Plex Sans Arabic للنصوص.
- `package.json`: أوامر build وtypecheck وtest وlint واعتماديات بيئة Grok.

## نقاط قوة قابلة للاستلهام

1. تسلسل سردي للصفحة: مقدمة، خدمات، قصة المكان، معرض، تجربة، زيارة.
2. تخطيط غير متماثل للصور والنصوص بدل شبكة بطاقات رتيبة.
3. محتوى عربي/إنجليزي ودعم اتجاهي RTL/LTR.
4. مراعاة الشاشات الصغيرة وتحميل الصور عند الحاجة وحركات ظهور هادئة.
5. مسار حجز منفصل وإمكانية تمرير خدمة محددة مسبقًا.
6. تحقق من مدخلات النموذج ورسائل نجاح.

## مخاطر وقيود

- الهوية الحالية أنثوية بصريًا ومضمونيًا؛ الصور تشمل الشعر النسائي والأظافر والمكياج والعروس.
- «ليان / Layan Atelier» والنصوص والأسعار والمدد أمثلة تخص الصالون النسائي وليست بيانات صالون رجالي.
- نموذج الحجز في `booking-form.tsx` تجريبي: يخزن الطلبات في `localStorage` مع تأخير محاكاة. هذا لا يثبت وجود backend أو إرسال حجز حقيقي.
- إعدادات WhatsApp فارغة؛ لا تدّعِ أن واتساب أو الحجز الفعلي متصل.
- لا تنقل نظام المصادقة أو قاعدة البيانات أو ملفات Grok/PWA لمجرد وجودها.
- لا تعدّل نواتج `.vercel/output/` بدل ملفات المصدر.

## الاتجاه المقترح لموقع رجالي

- هوية مميزة: فحمي/أسود، درجات حجرية أو رملية، ولمسة نحاسية أو زيتونية محدودة.
- صور مناسبة للحلاقة الرجالية: قصات شعر، تحديد لحية، أدوات حلاقة، كرسي الحلاق وتفاصيل المكان. استبعد صور الأظافر والمكياج والعروس.
- خدمات مرشحة للتأكيد: قص شعر رجالي، تهذيب لحية، باقة شعر ولحية، تحديد حواف، غسيل وتصفيف. لا تعرض خدمات غير متوفرة فعليًا.
- زر رئيسي للحجز، وثانوي لاستعراض الخدمات أو واتساب عند إضافة رقم صحيح.
- لا تخترع الأسعار أو المدد أو العنوان أو أوقات العمل؛ أخفِ غير المؤكد أو اجعله قابلًا للتعديل.
- إذا لم يوجد backend، سمِّ العملية «طلب موعد» أو «حجز تجريبي» بوضوح، ولا تعرضها كموعد مؤكد.

## خطة العمل

1. إبقاء ZIP الأصلي كما هو وحفظ هذا التقرير في Git.
2. فحص ملفات SIMT الحالية قبل أي تغيير ومقارنة ما يمكن الاستفادة منه.
3. اعتماد اتجاه رجالي واضح للألوان والخطوط والتصوير والنبرة وترتيب الأقسام.
4. تعديل ملفات المصدر في المشروع الحالي مع إزالة أي أثر لاسم ليان أو محتوى نسائي.
5. ربط الحجز بما هو متاح فعليًا فقط، مع توضيح حالته للمستخدم.
6. تشغيل lint وtypecheck والاختبارات والبناء، ثم مراجعة الموبايل وسطح المكتب.
7. تنفيذ العمل في فرع مستقل وفتح PR للمراجعة؛ لا تغيّر main أو تدمج تلقائيًا.
